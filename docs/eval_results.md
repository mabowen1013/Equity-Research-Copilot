# 评估结果与方法（Evaluation）

> 一份文档讲清三件事:**测了什么、结果如何、怎么算怎么测**。数据为 2026-06-30 在本地真实 DB/LLM 上跑出。
> 基调:除"结构化准确率"是大样本+置信区间外,其余是**小型 curated 集**——每个数都带 n,请连同 n 一起读。
> 复现见文末第 6 节。

---

## 1. 测了什么

按组件分层,5 个独立 harness,每个测 pipeline 的一环:

| Harness | 测哪一环 |
|---|---|
| `metric_accuracy_eval` | **数字对不对**:答案里的财务数字 vs SEC XBRL 真值（头条指标） |
| `retrieval_recall_eval` | **文本检索召回**:该命中的 SEC 章节在不在 top-5 |
| `retrieval_gold_eval` | **证据角色召回**:该出现的证据角色（财报/MD&A/风险/指标）有没有被检索到 |
| `answer_eval` | **端到端答案质量**:状态、引用、覆盖率、忠实度（蕴含）、安全拒答、延迟 |
| `agent_trajectory_eval` | **agent 工具选择**:非确定性 LLM 控制器选对工具吗、稳不稳 |
| `query_planner_eval` | **planner 槽位**:自然语言问题解析成的槽位对不对 |

## 2. 语料

## 4. 每个指标怎么算、怎么测

### 4.1 结构化指标准确率 = 86.5%（n=96,95% CI 78–92%）—— 头条
- **怎么生成题**:遍历 `financial_facts`,对「每家公司 × 每个金额指标（营收/净利/营业利润/毛利/经营现金流/自由现金流）× 最近 3 个财年」**自动生成**问题。不是手挑,所以无选择偏差;n=96。
- **真值**:就是 XBRL 那条 fact 的值(SEC 强制披露的结构化数据,外部真值)。
- **怎么判对**:跑完整 answer pipeline → 抽答案里的美元数字 → 比**首个**(headline)数字与真值是否在 **3% 容差**内。
  - ⚠️ **为什么比"首个"而不是"任意"**:答案带 YoY 上下文,会同时出现今年和去年两个数。如果"文本里出现过真值就算对",会把"把去年数说成今年"的错误**蒙混**过去。比首个数字才能抓到这种期间错配。
- **配置**:安全闸门关(纯测数字正确性),所以 0 拒答。只取最近 3 财年——更早的 XBRL facts 偶有错标。
- **故意不是 100%**,错误集中在:
  - **经营性现金流 12/18(67%)**:现金流量表是累计/YTD 口径,容易错。
  - **更早财年 FY2023 19/26(73%)**:历史财年查询会漂到最新年(实例:问 AAPL FY2024 营收,答成了 FY2025 的 $416B)。
- 报 **Wilson 95% 置信区间**。

### 4.2 文本检索 recall@5 = 91.7%（n=12）
- 12 道文本题（6 公司 ×「为什么类→该命中 MD&A」「风险类→该命中 Risk Factors」）。
- 跑真实检索 → 看 `retrieved_chunks` 前 5 个里,有没有一个的 `section_label` 命中期望章节。
- 章节匹配前**归一化**(去掉所有非字母数字),以容忍 SEC 标签的 OCR 噪声("RI SK FACTORS")。
- **指标类问题故意不计入**:它们走 XBRL 结构化数据答,不靠检索正文,由 4.1 覆盖。
- 唯一 miss:JPM 的 MD&A——它的 10-K 解析成了粗粒度的 "PART …" 标签(解析质量问题,非检索)。
- 严格说是 **top-5 章节命中率**(每题一个相关章节),口头叫 recall@5。

### 4.3 证据角色召回 = 100%（n=12）
- 12 题标注「该出现哪些证据**角色**」。看最终 evidence pack 是否填充了这些角色。
- **钉角色不钉 chunk ID**,所以重新摄取数据也不失效(旧版钉 `chunk:1252` 会 stale)。门槛偏低(角色非空即命中)。

### 4.4 answer_eval(端到端答案质量,n=24)
- 跑完整 run,**安全闸门开着**(部署配置:answerability + 蕴含)。每题查:状态、最少引用数、`expect_values`(数字真值)、句级覆盖率、`must_not_match`(禁投资建议)、延迟。
- **忠实度 0 矛盾**:对每个带引用的句子,LLM-judge 判 entailed/neutral/contradicted;0 矛盾。⚠️ judge **未对人工标注校准**,是信号非证明。
- **安全拒答 100%(5/5)**:对抗题(无关琐事、实时数据、银行毛利率)应返回 insufficient。
- **非法引用 0**:引用 marker 必须 ⊆ 检索证据,非法的出答案前剥掉——这是**构造性保证**,不是成就。
- **复合 pass-rate ~75%**:这是个合门(状态+引用+数字+覆盖率+安全+延迟)。失败项**几乎全是句级覆盖率没过 0.5 阈值**的、**数字其实是对的**答案——是覆盖率严格度信号,**不是答错**。所以我拆开报组件指标,而不是靠这个复合数。

### 4.5 Planner 槽位字段准确率 = 61%（n=46）
- 46 道歧义槽位题,每题标注期望的多个槽位。**字段级**:匹配字段数 / 断言字段数(全题加总)。
- ⚠️ 严格"全字段都对"的 **case-pass 只有 4.3%**,我**不报这个**——planner 核心槽位(问题类型/指标/章节)基本对,只在次要字段(comparison_basis、preferred_forms)和**部分过时的 gold** 不一致。字段级 61% 才是诚实测度;重新基线化 gold 是后续。

### 4.6 Agent 工具选择 100% / 稳定性 100%（n=10）
- 10 题标注「该用哪些工具」。每题跑 **2 次(清缓存)**,从 trace 读实际用的工具,要求「期望 ⊆ 实际」两次都过。
- ⚠️ 判据是**子集**(松)、工具映射"显然"、且 **temperature=0**,所以"稳定性 100%"几乎是白送的,别过度解读。

### 4.7 延迟 P50 13.4s / P95 19.3s（n=24）
- 24 个答案 run 的 `duration_ms` 取分位,**安全闸门开着**测,反映真实部署(带 answerability + 蕴含两次额外 LLM 调用)。

## 5. 这些数该信多少（可信度自检）

一墙的 100% 该警惕。分三类:

- **最可信的是结构化准确率 86.5%**:大样本(n=96)、外部真值(SEC XBRL)、自动生成无挑题、带置信区间、还诚实地**不是满分**。它是"数字走 XBRL 不走 LLM 猜"这个核心设计**确实有效**的证据。
- **高是因为门槛低/样本小/近乎确定**:安全拒答(n=5 且测例针对我自建的闸门)、agent 工具+稳定性(子集判据+temp=0)、角色召回(角色非空即命中)、非法引用 0(构造性保证)。这些别过度解读。
- **忠实度 0 矛盾**:可能真忠实,也可能 judge 偏宽——judge 未校准。

**不是全绿,恰恰说明 eval 没被凑绿**:结构化 86.5%、recall@5 91.7%(JPM 真 miss)、planner 61%(严格 4.3%)、覆盖率拖累的复合 75%。要更可信:独立第三方出题、更难的多跳/跨期题、agent 改精确匹配、检索做多相关标注的真 IR recall、给忠实度 judge 做人工校准。

## 8. 面试追问速答

- **"一堆 100%,是不是凑的?"** → 见第 5 节三分类:最硬的结构化准确率反而不是 100%;套件里有 86.5%/91.7%/61% 的非满分,证明没凑;那些 100% 多是低门槛/小样本/temp=0。
- **"结构化准确率多少、可信吗?"** → 86.5%(n=96,CI 78–92%):自动覆盖全部公司/指标/近 3 财年、对 SEC XBRL、比首个数字;弱项是经营现金流和老财年。最敢拿出去的数。
- **"稳定性 100% 怎么来的?"** → temp=0 + 子集判据,接近白送;真测稳定性得提温或上更模糊问法。
- **"planner 为什么报 61% 不报 4.3%?"** → 4.3% 是严格全字段伪影;核心槽位对、只在次要字段和过时 gold 不一致;字段级 61% 才诚实。
- **"忠实度 0 矛盾是系统好还是 judge 松?"** → judge 未校准,两种可能;答案多 grounded、低矛盾合理,但不当证明。
